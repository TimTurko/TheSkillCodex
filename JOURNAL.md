**La vérification en source a tenu son rôle d'anti-erreur sur trois specs RP2.** Le timer « matériel » du jumeau Arduino ne se transpose pas tel quel : sur RP2 `machine.Timer` est un timer **virtuel** cadencé par le matériel système, et la règle « pas d'allocation dans le callback » n'est universelle que pour un callback **hard IRQ** (`hard=True`) — par défaut le callback tourne en soft IRQ, où l'allocation est tolérée (au prix de la gigue GC). Le `deepsleep` du Pico a réservé deux pièges : le réveil sur broche depuis `lightsleep()` est un **bug connu ouvert** (documenté côté tracker), et `deepsleep` n'atteint pas les µA d'un AVR en power-down — c'est en pratique un alias de `lightsleep`. Ces trois points ont été lus en doc/tracker avant correction, jamais assénés de mémoire (prolonge C82 : *specs = source primaire*).

**Quand le SVG du jumeau encode une architecture étrangère, on ne le copie pas — on reconçoit (C84).** Trois fiches l'ont illustré : la `carte-memoire-sram` du jumeau (carte 3-mémoires AVR, `F()`/`PROGMEM`, collision pile/tas) n'a pas d'équivalent sur le modèle MicroPython → SVG-concept neuf **`fragmentation-tas`** (tas troué, plus grand trou < objet → `MemoryError`) ; la `carte-memoire-eeprom` octet-par-octet → **`persistance-fichier`** (RAM volatile vs fichier flash, le Pico n'ayant pas d'EEPROM) ; le profil de conso chiffré en µA → **`profil-courant-veille` « principe »** (faible/élevé sans µA, pour ne pas contredire la correction `deepsleep`≈`lightsleep`). C'est le pendant de la « copie locale C47 » : on copie quand l'architecture est commune (`boucle-fermee-pid`, `diagramme-etats`, `chronogramme-watchdog`), on reconçoit quand elle ne l'est pas.

**Clôture.** Le §13 est le **premier module famille MCU entièrement relu en mode inversé** (38 fiches, sessions 29-30/06). Les 14 dernières cases du dashboard sont cochées (rendus validés), le bandeau passé à « TERMINÉE ». **Reste à Tim** : commit/push ; **relire l'ajout de section « Servos à retour de position » de `micropython-servomoteur`** (signalé [gros ajout]) ; captures C29 matérielles (Shell Thonny, multimètre veille, REPL `gc.mem_free()`…) ; **audit des liens entrants `[[micropython-eeprom]]`** résiduels. **Prochaine session = MAJ documentaire** dédiée : **archiver les entrées anciennes du JOURNAL** (cible 08-19/06 → `JOURNAL-archive.md`, marqueur `<!-- INSERT_JOURNAL_HERE -->` préservé) pour repasser sous 100 ko, puis reprise relecture **§14 Raspberry Pi** (médias en place).
